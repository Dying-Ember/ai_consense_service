# Drafting context preservation and bounded recall

2026-10-06. Authorized by the user after diagnosis: preserve logical context and look before/after a missed input, without guessing missing values. This extends the existing extraction harness spec and its agreed public upload/extract/variables/trace interfaces. Current catalogue, adoption, DOCX generation, provider selection and other modules retain their existing behavior.

Diagnostic baseline: `local verification artifact (not published)`. Captured run `0b9ae48b-0310-44c3-9969-3eb6b66a272a` split the NTT13 title/instruction into part 87:1 and the complete answer into 87:2. No nonblank nsc candidate reached intake. A configured MiniMax-M3 pair recovered the entire answer when only the preceding original title/instruction was restored. This is a source organization failure and bounded semantic observation, not an overall model acceptance result.

## Required behavior

1. Preserve the full uploaded correspondence and native source identities. Organize requests around complete paragraphs, headings/instructions with their following text, and table headers/rows where available. Oversized content remains budgeted; no text is silently lost. Structural context must be original uploaded text, not synthesized project facts. Keep unchanged source IDs/hashes and original offsets for every added window.
2. Keep existing legacy trace fields, primary responses and per-item decisions inspectable. A primary source part can remain stable while its request receives a contiguous original-source window around its edge. Record the actual window separately when it differs from the core part, and validate quotes against what was actually supplied. Do not falsely reject a valid quote from added context, or accept a quote that was not dispatched.
3. Add a distinct bounded `recall` attempt for an editable field with source-local association cues but no usable local candidate. Cues can come from field meanings/aliases, clause targets or explicit continuation/adoption headings; do not recognize SIM filenames, expected answers or hard-code NTT13 behavior. The catalogue is routing/schema information, never value evidence. Use a compact catalogue containing only the targeted keys. Preserve customized instructions.
4. First recall window covers the relevant complete logical unit and its same-document neighbors, respecting the next topic and a finite source window budget. At most one recall per part/evidence cluster, with no recursive retry. If explicit source references require another uploaded document, a second bounded related-source pass is permitted; otherwise stop after the local attempt. Impose a finite per-run recall cap. Never concatenate unrelated projects, templates, reference answer files or the entire corpus by default.
5. Distinguish missing model output, ordinary model null, explicit source pending, exhausted local search, insufficient context and provider failure. Ordinary null may be recalled when neighboring supplied evidence exists. A local failed search cannot prove every correspondence lacks an answer. Explicit pending remains unresolved unless other actual uploaded passages provide a later explicit answer. Do not populate deliberate missing-evidence inputs, infer values from defaults or turn unknown into false/empty lists.
6. Determine conditional recall eligibility using current manual values and this run's parent suggestions, conservatively retaining unknown/conflicting applicability. Do not skip a newly applicable branch because an old unadopted parent value was different. Definitely inactive/hidden/derived fields need no recall; retained values must not be cleared.
7. Every recall output passes the existing type, literal-value, contiguous quote and confidence checks, with a targeted-key allowlist. Preserve original null/rejected/missing outcomes and new failures. Repeated overlapping references must not vote for a value or manufacture extra independent support. Contradictory sourced values remain candidates for human review; upload order alone cannot decide an amendment.
8. Existing concurrent/manual/adopted value protection and evidence-revision atomicity remain authoritative. Recall creates editable suggestions only, never adoption or silent overwrites. Provider profile remains frozen per extraction. A recall failure is retained and identified; obey explicit-provider failure policy rather than silently switching models.
9. Additive frontend diagnostics support `recall` and its metadata in Simplified Chinese, Traditional Chinese and English. Existing layout, editors, filters and template preview behavior stay unchanged. Older traces remain renderable.

## Additive trace contract

`attempts[].kind` adds `recall`. Optional `attempts[].context` is an object with `trigger` (string), `keys` (string[]), `sourceStart`/`sourceEnd` (zero-based UTF-16 half-open offsets), `sourceText` (exact dispatched original passage), `stopReason` (string). Primary contextualization may use the same metadata. Optional part-level context/recall planning metadata can retain non-dispatched budget/eligibility stop reasons. Existing constructor callers and historical JSON remain compatible.

New intake codes: `recall_key_not_allowed` and `context_incomplete_source`. The latter rejects text/list fragments whose original paragraph/table is cut by the supplied window budget; exact quotation alone does not establish a complete replacement or list. Other complete passages in the request can still support their own candidates. Existing `model_call_failed` and `invalid_json` still describe attempt failures. Stop reasons use `candidate_found`, `no_supported_candidate`, `explicit_pending`, `context_insufficient`, `budget_exhausted`, `model_call_failed`, `invalid_json`, `inactive`, `no_source_cue` as needed. Every emitted frontend-facing code/reason receives three translations or a safe explanatory fallback.

Same-source text candidate identity uses the same typographic quote and whitespace equivalence already accepted by quotation validation. Two complete accepted text values from the same original document ID/hash that differ only in those forms must not create duplicate support or a false conflict. Compare symmetric equality of the complete canonical text, never substring containment; retain the first actual value/quote and every raw decision unchanged. Distinct text, non-text values and separate source provenance retain their existing treatment. This clarifies requirement 7 after actual M3 run `3a93b603-d627-4784-ba17-e62e46248270` returned the same full NTT13 paragraph twice with curly/straight apostrophes.
