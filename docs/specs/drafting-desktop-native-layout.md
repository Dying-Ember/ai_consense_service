# Registered native continuation layout for explicit Desktop rendering

The assessed free Desktop converter ignored pageBreakBefore inside continuation-title table cells. The supplied NTT/SCT manually placed their page furniture and many continuation tables without a forcing BODY break. Original source/draft conversion could consequently put the next title below the prior manual footer. Adding only native BODY breaks exposed one NTT date-only page and two SCT source blank pages; exact, source-guarded empty spacers were identified causally. Full causal variants and failed observations remain outside the repository in `hw07/x2t-continuation-diagnosis-01`.

The optional `desktop-native-continuations-v1` policy is applied when the configured renderer kind is `desktop-x2t`. The resource `drafting/desktop-native-layout.json` registers immutable original source hashes and original native table, first-row heading, preceding footer and empty-paragraph anchors. NTT registers9 boundaries (11 original titles minus opening/existing first native break) and excludes only original P410/P592. SCT registers25 (27 minus opening/existing first break) and excludes only P878/P879/P913/P914/P915. These seven exact source nodes are never current paragraph numbers, page coordinates or a general empty-paragraph rule. SCC is unchanged. An unknown/modified source edition preserves its current native content and returns an explicit skipped-layout diagnostic.

`DocxTemplateEditor` captures verified source Elements before business edits. It applies layout to surviving original table/heading objects after the business batch, before original CS markers and serialization. Removed subtrees are checked against the document root and recorded as skipped. An unexpected nonempty/mutated registered spacer, changed table/heading relation or cleared/replaced original heading is refused. Only the captured heading's original native hash is checked after edits; legal changes to other paragraphs in the table do not invalidate it. Added empty BODY paragraphs carry pageBreakBefore, zero before/after spacing and one-twip exact line height. Deterministic CL bookmarks identify only these protected layout controls; they do not create business targets, evidence or adoption actions. Existing original text, native bookmarks, field controls, paragraph/run/table properties and opaque package parts remain preserved apart from the seven explicitly registered empty exclusions.

Generation persists the resulting DOCX as the new revision before preview/export. DOCX export and PDF input use those exact stored bytes, guarded by revision/DOCX hash and actual rendering profile. Source preview and source binding bundles build the same deterministic annotated/layout working copy, with its own DOCX hash and the unchanged raw source hash. The original upload/download remains byte-identical. Default LibreOffice creation passes no layout plan.

Layout provenance is a separate `native_layout` entry in the existing ledger JSON, exposed read-only as optional `nativeLayout` on document and binding DTOs. It contains profile, status, sourceSha256, current docxSha256, immutable compiledDocxSha256, optional parentDocxSha256 and actions. Each action records source native ID/hash, insertion/removal/skip status, current generatedId and CL layoutId where applicable. Body saves preserve the existing layout, retain compiled/source identities, update current/parent hashes and reconcile current layout paths through complete CL markers. They do not apply the source policy again.

Old saved artifacts with no recorded policy return `not_applied_to_saved_revision` when Desktop is requested. Reads and engine switches never retrofit or regenerate their body, fields, ledger or bytes. An explicit future repair operation for old human-edited revisions is outside this change. Unknown source is `skipped_unverified_source`; missing layout-marker reconciliation is `unavailable`. Applied means this bounded native policy is recorded, not a certificate for every physical page or Word fidelity.

Public acceptance uses actual template upload/source preview, generation, body save and same-revision export interfaces in isolated H2/storage with provider services disabled. It includes all original registered SCT continuations; L10Pro/two-envelope surviving20 and removed5; strict native comparison against the same adopted business output after reverting only registered controls/CL pairs/empty exclusions; opaque parts; protected empty edit refusal; NTT/SCT LF/Tab and inserted body paragraphs; immutable/stale revision guards; raw source preservation; unknown-source skip; and an old human body preserved across renderer change. Prior false-pass text-fragment assertion, actual source9-collision RED, native export0-versus9 RED and incomplete fixture21-versus20 failure are retained separately.

The first public NTT saved-body packet exposed a completely blank physical page11 after two saved lines overflowed the original empty P592 following footer10/date. Adding keepNext only to the new CL paragraph did not fix it. Derived source-working/current-generated/current-saved copies removed only exact source P592:11/11/12 pages became11/11/11 with no blank/furniture-only pages, exact ordered glyph/font/title/footer sequences, reversible native XML and byte-identical opaque parts. Both failure packets are retained. A public saved-body no-blank assertion and public editor clear/replace-heading refusal now cover these boundaries.

The Desktop public harness accepts an explicit short owned `consense.acceptance.desktopWorkRoot`. An actual238-character conversion-copy path rendered readable content but lost the expected paragraph URI point; the exact same conversion-copy bytes at72 characters restored it. The failed63-test packet is retained and actual-point assertions remain unchanged. Deployment uses an explicit short work root; arbitrary long Windows paths are unaccepted and individual missing locations remain unavailable.

The derived old SCT draft has a substantive sparse overflow page containing two actual clause lines and furniture. It remains visible. Arbitrary longer adopted/body text may legitimately overflow, and the policy does not dynamically repaginate by physical observations. SCC's real TOC/section flow is untouched. Native Word reference layout, full editor deployment, whole-workspace acceptance and ticket completion remain separate.
