# Explicit LLM source selection

Status: implemented and accepted for bounded routing/persistence/UI scope, 2026-10-06; see A16 verification (internal implementation/verification record; not published) for actual provider checks, limits and a concurrent pre-deployment demo extraction. User requests explicit local compute or MiniMax China Token Plan selection. This extends the isolated integration; it does not change drafting business rules, extraction/adoption policy, document compilation, index contents or original checkouts.

## Public contract

1. Add a shared top-bar selector in Simplified Chinese, Traditional Chinese and English. Choices are `local` and `minimax-cn`. Show the configured chat model beside the choice. Explain that changes apply to new operations. Persist only the chosen ID in browser localStorage (`consense-llm-profile`); no browser API key, server-global settings mutation or automatic fallback.
2. `GET /api/system/llm-profiles` returns the existing success envelope containing `{ defaultProfile, profiles: [{ id, provider, model, configured, unavailableReason? }] }`. Exactly the two supported IDs are listed. Readiness means configuration present, not authenticated inference or quota proof. Reason codes are stable, including `missing_api_key` / `disabled` / `missing_configuration`. Metadata itself performs no model call and contains no credential. A valid persisted but unconfigured choice stays visible until the user changes it. Unknown stored IDs use the declared default with a visible usable selection.
3. Existing model operations accept `X-ConSense-Llm-Profile: local | minimax-cn`. Missing header keeps legacy deployment behavior. Unknown ID produces a visible 400; selected unconfigured profile produces a visible configuration error on a model operation. Safe metadata, history and deterministic document downloads remain readable regardless of selected provider availability. CORS permits the header. No request may supply its own base URL, model or key.
4. Source selection is immutable for each operation, captured at user action entry before any await, then resolved once on the server. All primary, JSON retry, repair and structured calls retain that selection. A different concurrent request may use the other profile. Vetting captures the selection before queueing and restores the worker context in finally. Existing active-run reuse returns the original run identity rather than relabelling it.
5. Explicit profiles route chat only. Embeddings, OCR, vector collection and indexing retain the current deployment configuration; embedding availability is independent of selected chat availability. Explicit selection must not be overridden by the legacy Vetting Responses flag. Preserve header-absent legacy Responses behavior; explicit profiles use their matching Chat Completions/session budget and observer, with unknown/unmeasured capacity represented honestly.
6. Add persisted safe model identity `{ profileId, provider, model, configurationSha256, identityScope: 'configured_profile' }` where practical to Drafting extraction trace/history, queued/completed Vetting result and Advice response/history. It describes the selected configured adapter, not provider-attested model execution. Old records remain missing/unknown, never relabelled with the current selector. Native DOCX compilation does not acquire a fictitious LLM identity.
7. Configuration/connection/authentication/quota failures visibly fail the selected model operation; do not route to the other provider, return a deterministic-only result pretending to be model output, or convert provider failure into a no-evidence Advice answer. Existing true no-evidence behavior remains. Preserve failure trace/report evidence and manual adopted values.

## Profiles

- `local`: current `consense.llm` chat settings and adapter, unchanged (the owned preview currently uses Ollama `qwen2.5:7b-instruct-q4_K_M`). The default deployment continues to own embeddings.
- `minimax-cn`: separate server-owned configuration, OpenAI-compatible adapter, default endpoint root `httplocal verification artifact (not published)`, default model `MiniMax-M3`; dedicated key `${MiniMaxCN_Token_Plan_API_Key:}` only, without pay-as-you-go credential fallback. Configuration fields must be separate from the legacy Llm bean to avoid recursive initialization or mutable singleton switching. Keep reasoning separate from answer content; use documented `reasoning_split=true` and disabled thinking for structured extraction. Model/endpoint remain deployment-configurable. Do not serialize secrets or include them in command lines, client errors, traces or configuration fingerprints.

Official protocol references verified 2026-10-06: httplocal verification artifact (not published)`/v1/chat/completions`, so store the endpoint root without `/v1`. A configured key alone does not prove active subscription/quota.
