# Drafting document engine decision

2026-10-07. Incremental decision for HW-03 and HW-07. The evidence-hardening/workspace specification and frozen business rules remain authoritative.

Continue implementing the free LibreOffice renderer with PDF.js and revision-bound semantic bookmarks. Keep ONLYOFFICE Community with an internal plugin as the first candidate for a native office workspace on a supported, scoped host. A native editor has not been deployed or accepted on this Windows 11 machine. This decision does not certify current pagination, Word layout fidelity, field refresh or the complete document workspace.

The actual six original/saved NTT, SCT and SCC packages were converted. Existing LibreOffice source/draft counts are 16/14, 32/25 and 94/91. Portable ONLYOFFICE Builder 9.4 produces 12/11, 28/22 and 81/78 and preserves body paragraph text/order and table counts on no-op DOCX roundtrips. Its PDFs visibly contain a graphical Unregistered Version watermark, including pages whose extracted text has no watermark. It is evaluation evidence, not a free production exporter. [Builder installation and limits](httplocal verification artifact (not published)

Aspose.Words Java 26.9 without a license retains only about 202–207 paragraphs from each real package and exports 5–6 pages with evaluation notices and an explicit truncation message. It cannot verify full-template fidelity. Preserve it as a paid comparison candidate; make no purchase or unrestricted-fidelity claim from this trial. [Aspose licensing restrictions](httplocal verification artifact (not published)

The current host has no established Docker/WSL deployment, and official Windows Docs Community deployment remains a Windows Server/service route. The current 9.4 Community release removed its former 20-connection limit; do not repeat that older restriction. The internal plugin API documents content-control selection and focus/change events. The external Automation Connector is a Developer capability with separate pricing; a free authenticated app/plugin bridge needs a real pilot. [Windows requirements](httplocal verification artifact (not published)

Invisible alphanumeric paragraph bookmarks in immutable-source-derived copies resolve to physical PDF page/point destinations when LibreOffice's ExportBookmarksToPDFDestination option is enabled. A local pilot resolves all 178 NTT original and 304 SCT saved-document markers without changing original bytes, body text or table counts. This is point-location proof, not full text rectangles or native editor acceptance. Initial underscore/name decoding failure is retained; canonical binding IDs avoid punctuation. [LibreOffice PDF filter options](httplocal verification artifact (not published)

The public Java conversion seam reproduced missing destinations on the actual bookmarked template. The first filter change still failed because embedded JSON quotes were not delivered correctly by the Windows process launch. Escaping the filter argument on Windows then resolves all 178 actual markers. The canonical filter participates in the render-profile hash, with a new adapter version; old PDFs and coordinates cannot be reused as current under the new profile. Original and exported DOCX are never silently resaved by the renderer.

The accepted Windows command is the explicitly configured portable `soffice.com`: public Java tests resolve NTT 178/178 and SCT 304/304 destinations. A separate `soffice.exe` compatibility run times out during executable identification, before PDF export; its failure is retained and owned processes are stopped. Do not claim that this `.exe` path is supported from the `.com` result. Comparing all 16 NTT and 25 SCT pages before and after marker/filter insertion gives identical rendered pixels on every page. This proves that the invisible markers preserve these existing renderings, including their existing pagination defects.

Pagination remains a separate acceptance task. Real original documents contain manual page furniture, long runs of empty paragraphs and non-splitting clause tables. A read-only LibreOffice UNO observation confirms the NTT opening furniture moves onto another physical page. Disabling AddExternalLeading in a temporary in-memory experiment reduces NTT to 14 pages, but leaves a March 2020 furniture-only page. This experiment is not a production correction. Do not delete blank pages, change original paragraph styles globally, or declare fidelity from fewer pages. An installed Word reference attempt produced no output and was stopped as an owned-process timeout; there is no Word reference baseline. Different converters all retain the saved SCT Bill 3–9 missing descriptions. The adopted identities and unknown purpose/placement are separate: do not fabricate distribution metadata or silently bypass existing business requirements. Compiler fixes must follow already determined actions; the workspace must expose unapplied locations clearly.

Evidence is append-only under `local verification artifact (not published)`: `hw03/engine-pilot-report.md` contains receipts, tagged license sources, six conversions and visual renders; `layout-reference/binding-pilot-002/` contains the free marker proof; `hw07/red01/`, `green01/` (failed first fix) and `green02/` contain the actual service converter test artifacts. Body editing, multi-target bindings, original/result/evidence navigation and same-revision browser/export acceptance remain required before the overall goal can be closed.
