## Requirements

P1. Preserve prototype A's single vertical editable question list and current competition catalogue, business rules, extraction harness, source roles, manual priority, document identity, and Word/PDF export. Add an optional template-reading side panel in the variable step; the generated-document preview remains separate.

P2. Read the project's actually uploaded NTT/SCT/SCC DOCX. Display its content using a DOCX-to-HTML reading preview. Clearly label this view as template reading rather than final Word layout. PDF templates may use the existing PDF viewer with an explicit text-navigation limitation. Unsupported formats or missing/corrupt sources show actionable errors, not an empty success.

P3. A field or clause-location click opens the appropriate file and locates its source text. A source marker click selects and scrolls to its input; preserve unsaved values and clear obstructing search/status filters. Multiple linked fields/targets remain individually selectable. Enumerate multiple locations, allow next/previous and direct selection, and show the current/total count. File switches, project switches, close and language switches must not display stale fetch/conversion results.

P4. Prefer the current action's source text and verified paragraph scope; source metadata uses native OOXML paragraph identities from the same uploaded bytes/hash. Only label an anchor exact when its source paragraph identity/text mapping is unambiguous. A catalogue range is valid only against its verified source edition; replacements must not silently reuse historical ordinals. Weak term/placeholder matches are navigation fallbacks, explicitly labelled approximate; they cannot decide clause treatment. Report missing locations and ambiguous matches honestly. Use native main-document paragraph order, including table cells, consistent with existing source editor.

P5. Show current values and their actual adoption/review/unsaved/inactive status near located text and in a selected-field card. Reuse existing field labels, stable option values, evidence and related actions. Card shows current field, source/candidates and all affected document/clause locations; exact-target editing invokes the existing action-id override flow.

P6. Simple text/number/date/select/boolean inputs can be edited from the preview using the same field component and shared local values as the main list. Editing alone never silently adopts an untouched model suggestion. Explicit save of a genuine manual change follows existing manual-adoption rules; explicit adoption uses existing adoption API. Keep other unsaved fields through refresh. Structured values use a return-to-input action. Clearing, unknown values, dependent applicability and trilingual labels follow existing rules. Editing affects shared local plan/value display; existing generated documents require regeneration and retain revision-bound export safeguards.

P7. Add a correspondence removal button and filename confirmation dialog. Reuse existing DELETE API semantics: remove from active project inputs, retain original stored evidence, flag linked values for review; do not promise physical/index deletion. Refresh correspondence, values, plan and document metadata after success, retaining unrelated unsaved inputs. Failed removal retains the item and reports the failure.

P8. All new controls/status/errors support en, zh-Hans and zh-Hant. Keep source English and generated documents English. Loading, missing anchors, unsupported sources and errors are separate states. Sanitise converted HTML (including links/images) before rendering: uploaded document contents are untrusted. Do not change user templates or silently regenerate documents. No credentials in code/logs.
